# ADR 0002: Основная метрика и baseline для ЛР4

## Статус

Предложено для review в рамках [issue #32](https://github.com/haiksarg/T26_MLOps/issues/32).

Дата: 2026-10-23. Автор: @Sheremgato, команда №4.

План и гиперпараметры фиксируются до сравнительных запусков.

## Контекст

В ADR 0001 основной метрикой проекта выбрана RMSE. Для эксперимента ЛР4 по треку 6
нужно сравнить прогноз с простой точкой отсчета и оценить устойчивость результата
при разных разбиениях California Housing. Пользователю понятнее средняя абсолютная
ошибка в долларах; RMSE дополнительно показывает влияние больших промахов.

## Решение

### Метрика и точка отсчета

Основная метрика ЛР4 — MAE на test в USD, меньше — лучше. Это уточняет выбор метрики
из ADR 0001 для данного эксперимента. RMSE сохраняется как дополнительная метрика:
она сильнее штрафует большие ошибки, поэтому расхождение MAE и RMSE полезно объяснять.

Baseline — `DummyRegressor(strategy="median")`: для любой строки прогнозируется
медиана `median_house_value` только по train. Медиана минимизирует абсолютную ошибку
константного прогноза. Его MAE записывается как `baseline_mae`; относительное улучшение
модели — `mae_skill = 1 - mae / baseline_mae`. Ноль означает уровень baseline,
положительное значение — улучшение, отрицательное — ухудшение.

### Что фиксируем

- Полный набор California Housing из принятой ЛР3 (`lr3-v1`), 20 640 строк.
  SHA-256: `8a3727f4cf54ac1a327f69b1d5b4db54c5834ea81c6e4efc0d163300022a685e`;
  DVC MD5: `d1c47305887e2252bf1ccbd74ff159a6`; контракт `1.0.0`.
- Разделение ЛР3: test 20%, стратификация по `median_income` с границами
  `[0, 1.5, 3, 4.5, 6, +inf]`. Для одного seed все модели получают одинаковые строки.
- Девять признаков из `FEATURES`; цель в признаки не входит. Предобработка ЛР3:
  медианная импутация, StandardScaler, OneHotEncoder с `handle_unknown="ignore"`.
  Все преобразования обучаются только на train.
- Версии библиотек из `pyproject.toml`; каждый run хранит Git SHA, признак изменений
  рабочего дерева, SHA-256 данных, DVC MD5 и версию контракта.

### Варианты и гиперпараметры

Единственный сравниваемый фактор — `train.model` в `params.yaml`:

| Значение | Модель | Зафиксированные настройки |
|---|---|---|
| `median_baseline` | Константный прогноз медианой train | `strategy="median"` |
| `linear_regression` | Линейная регрессия | `LinearRegression()` без подбора параметров |
| `random_forest` | Случайный лес | `rf_n_estimators: 100`, `rf_max_depth: 12`, `random_state=seed`, `n_jobs=-1` |

Сто деревьев усредняют отдельные случайные деревья и сохраняют приемлемое время
локального запуска. Глубина 12 ограничивает сложность по сравнению с неограниченным
ростом деревьев. Эти значения выбираются заранее как учебная конфигурация, а не
подбираются по test. Линейная регрессия дает простой обучаемый вариант, лес позволяет
проверить пользу нелинейных зависимостей. Другие варианты в эту серию не добавляем.

### План сравнения

Используем seed `42, 7, 13, 21, 99`. Seed задает разделение train/test и случайность
леса; для baseline и линейной регрессии разброс связан с разбиением. Плановая серия —
ровно `3 × 5 = 15` завершенных запусков. Проверочные запуски установки и сериализации
не являются дополнительными попытками подбора модели и не входят в итоговую серию.

Для каждого вида считаем среднюю MAE и выборочное стандартное отклонение по пяти seed.
Вариант с меньшей средней MAE признаем лучше только при
`abs(mean_mae_1 - mean_mae_2) > 2 * max(std_mae_1, std_mae_2)`.
Сравниваем варианты с baseline и лучший вариант со следующим. Если порог не превышен,
устойчивое превосходство по учебному критерию не подтверждено. Это правило курса,
а не доказательство статистической значимости для любых данных.

Test не используется для подбора гиперпараметров. Сравнение трех заранее заданных
моделей выполняется по методике командной issue; после просмотра результатов нельзя
незаметно добавлять попытки или менять настройки. Итоговую серию и сравнение оформляет
@icy07 в issue #33. До принятия решения значения остаются
`train.model: median_baseline`, `train.seed: 42`.

## Последствия

Получаем понятную точку отсчета и сравнение с учетом разброса, а не только одного seed.
Отрицательный результат допустим: новая модель может не показать устойчивого улучшения.
Запуски с разными SHA-256 данных нельзя включать в одно сравнение.

Сохранение через skops требует проверить фактические недоверенные типы обученного
pipeline. Разрешаем только обоснованные типы для конкретного вида модели и проверяем,
что загруженный pipeline повторяет предсказание; проверку не обходим через pickle.

Ограничения сохраняются: районы Калифорнии 1990 года, верхнее ограничение целевой цены
500001 USD и пространственная близость наблюдений. Случайное разделение не доказывает
переносимость на другие годы, регионы или отдельные объекты. Сравнение по test в этой
учебной серии не является новой независимой оценкой уже выбранной по нему модели.
