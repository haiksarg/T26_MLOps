
# Карточка набора данных — California Housing

## 1. Название, назначение и ограничения использования

Название: California Housing.

Набор используется в учебном MLOps-проекте для прогнозирования медианной стоимости жилья в районах Калифорнии.

Предполагаемый пользователь — аналитик недвижимости, изучающий различия между районами.

Данные не предназначены для:
- оценки стоимости конкретной квартиры или дома;
- принятия кредитных или страховых решений;
- анализа современного рынка недвижимости;
- принятия решений, непосредственно затрагивающих права людей.

## 2. Происхождение, владелец и период данных

Исходные сведения получены в рамках переписи населения США 1990 года.

На их основе R. Kelley Pace и Ronald Barry подготовили набор, описанный в статье "Sparse Spatial Autoregressions" (1997).

Дальнейшая цепочка происхождения:
1. Репозиторий StatLib.
2. Страница Luís Torgo, University of Porto.
3. Публичный репозиторий Aurélien Géron `ageron/handson-ml2`.
4. Учебный образец нашего проекта.

В версии Géron удалены 207 значений `total_bedrooms` и добавлена категория `ocean_proximity`.

Версия источника зафиксирована коммитом `aa555aa16b9d0af6c84e67c7757f3317d05acb12`.

В проекте используется образец из 40 случайно выбранных строк с `seed=42`. Порядок и значения строк сохранены. Подробности получения и контрольные суммы приведены в `data/README.md`.

Исходные данные относятся к переписи США; Pace и Barry подготовили исследовательский набор, Géron — его учебную модификацию. В команде за описание происхождения, обновление и удаление отвечает Data steward.

## 4. Состав полей и целевая переменная

Одна строка описывает census block group — территориальную группу кварталов, а не отдельный дом.

Входные признаки:
- `longitude`, `latitude` — географические координаты центра группы;
- `housing_median_age` — медианный возраст жилья;
- `total_rooms` — общее число комнат;
- `total_bedrooms` — общее число спален;
- `population` — численность населения;
- `households` — количество домохозяйств;
- `median_income` — медианный доход домохозяйств;
- `ocean_proximity` — категория расположения относительно океана.

Целевая переменная:
`median_house_value` — медианная стоимость жилья в долларах США.

Цель берется непосредственно из исходного столбца, дополнительное вычисление класса или преобразование ответа не требуется.

Точная схема, типы и диапазоны полей определяются в `data/contract.json`.

## 5. Размер, единицы измерения и пропуски

Полный набор содержит 20 640 строк и 10 столбцов.

Учебный образец в Git — 40 строк и 10 столбцов. Он используется для проверки инфраструктуры, а не для получения статистически надежных результатов модели.

Единицы измерения:
- координаты — градусы;
- возраст жилья — годы;
- число комнат, спален, жителей и домохозяйств — соответствующие единицы счета;
- `median_income` — десятки тысяч USD в год;
- `median_house_value` — USD;
- `ocean_proximity` — категориальное значение.

В полной модифицированной версии Géron намеренно отсутствуют 207 значений `total_bedrooms`. Контракт разрешает пропуски только в этом поле.

Фактическое число пропусков в конкретном образце проверяется валидатором; их наличие не должно считаться ошибкой, если контракт допускает nullable.

## 6. Чувствительные данные и обезличивание

Набор не содержит имен, персональных идентификаторов и индивидуальных адресов.

Каждая строка представляет агрегированные характеристики census block group (обычно от 600 до 3000 жителей). Координаты указывают на центр группы, а не на адрес конкретного человека.

Дополнительное удаление персональных идентификаторов для данного учебного образца не требуется.

При переходе на более детальные данные необходимо отдельно проверить риск повторной идентификации и права на публикацию.

## 7. Репрезентативность и известные смещения

Основные ограничения:

1. Данные относятся к 1990 году и не отражают современный рынок.
2. Географический охват ограничен Калифорнией.
3. Используются агрегированные показатели районов, а не характеристики отдельных объектов.
4. Значения `housing_median_age`, `median_income` и `median_house_value` ограничены сверху значениями 52, 15.0001 и 500001 соответственно.
5. Категория `ISLAND` представлена только пятью строками в полном наборе.
6. Образец из 40 строк не позволяет надежно оценивать качество прогнозирования или распределения редких категорий.

Поэтому результаты нельзя без дополнительной проверки переносить на другие штаты, годы и индивидуальные объекты недвижимости.

## 8. Стратегия разделения и предотвращение утечки

Для полного учебного набора выбирается воспроизводимое случайное разделение train/test с `random_state=42`.

Стратификация проводится по категории медианного дохода `median_income`, разделенного на пять интервалов: до 1.5, 1.5–3, 3–4.5, 4.5–6 и выше 6 (в единицах исходного признака).

Это позволяет приблизительно сохранить распределение важного для цены признака в обучающей и тестовой частях.

Образец из 40 строк не используется для надежной оценки модели; перед применением стратификации необходимо убедиться, что в каждом интервале достаточно наблюдений.

Меры против утечки:
- `median_house_value` используется только как TARGET и не входит в FEATURES;
- признаки, вычисленные из целевой переменной, запрещены;
- заполнение пропусков `total_bedrooms` обучается только на train;
- кодирование `ocean_proximity` настраивается только на train;
- параметры масштабирования вычисляются только на train;
- тестовая выборка не используется при подборе параметров и обучении;
- в прогноз передаются только признаки, доступные на момент предсказания.

Из-за пространственной близости соседние block groups могут быть похожи. Случайное разделение способно завысить оценку качества. Для более строгой оценки следует дополнительно рассмотреть географическое групповое разделение (group split) по регионам.

## 9. Обновление, версионирование и удаление

За актуальность карточки, происхождение и безопасную публикацию набора отвечает Data steward.

При обновлении:
1. Фиксируется новая версия и источник данных.
2. Проверяется допустимость использования.
3. Рассчитывается новый SHA-256.
4. Обновляется `data/README.md`.
5. Сверяются поля и правила с `data/contract.json`.
6. При необходимости изменяется версия контракта.

Правило версионирования контракта:
- patch — уточнение документации без изменения проверки;
- minor — совместимое добавление необязательного поля;
- major — несовместимое изменение структуры, типа или смысла поля.

В Git не добавляются закрытые наборы, секреты и необезличенные персональные данные. Полные и производные файлы хранятся вне Git по политике проекта.

Версионирование полного набора через DVC планируется в ЛР3.

Если чувствительные данные попали в историю Git, необходимо остановить публикацию, уведомить ответственного и выполнить согласованную процедуру очистки истории. Обычное удаление файла новым коммитом недостаточно.
